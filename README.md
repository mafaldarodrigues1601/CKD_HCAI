# CKD_HCAI: An Agentic Decision-Support System for Early Chronic Kidney Disease Detection and Nephrology Referral

Code, results and paper for the Human-Centered AI (HCAI) course project.

The system supports a general practitioner in screening for chronic kidney disease (CKD) from routine clinical data. It combines a calibrated classifier, SHAP explanations, KDIGO-inspired referral criteria and a tool-using language-model agent. Cases the model is unsure about are deferred to the physician. An active learning study shows how few labels are needed to train the model.

**Authors:** Mafalda Martins Rodrigues, Carolina Picado, Martim Robalo.

> **Disclaimer.** This is an academic prototype for decision support. It is not a medical device and does not replace clinical judgement. Diagnosis and referral are always the physician's decision.

## Main results

All numbers come from the UCI CKD dataset (400 patients, 24 variables) with a fixed stratified 80/20 split (`random_state=42`). Model selection uses only the training set.

| Item | Result |
|---|---|
| Selected model | Logistic Regression (cross-validated sensitivity 0.994 ± 0.013, 5×10 repeated CV) |
| Decision threshold (sensitivity ≥ 0.98 on out-of-fold predictions) | 0.642 |
| Test set (n = 80), final model | sensitivity 0.960, specificity 1.000, AUROC 1.000 |
| Uncertainty zone (deferred to the physician) | predicted probability 0.25 to 0.75 |
| Active learning, labels needed to reach sensitivity 0.95 | median 14 (uncertainty sampling) vs 23.5 (random sampling) |

The paper describes the methods, experiments and limitations in full. The dataset is small and mostly well separated, so the results should not be read as evidence of clinical performance.

## Repository structure

```

  ckd_uci.csv                 UCI Chronic Kidney Disease dataset

  config.py                   project paths (single place)
  Prep_Data.py                cleaning and encoding; dividir(X, y) gives the one 80/20 split
  comparar_modelos.py         1) model comparison: repeated CV, model selection, test set
  limiar_calibracao.py        2) probability calibration (Brier) and threshold selection
  graficos_finais.py          3) ROC, confusion matrix, CV table, variable-group ablation
  comparacao_folds.py         paired comparison of the models over the CV folds
  explicar_shap.py            global and per-patient SHAP explanations
  testar_casos.py             end-to-end example cases (clear CKD, borderline, healthy)
  active_learning_ckd.py      4) active learning: uncertainty vs random sampling
  descricoes.py               variable names, units and valid ranges
  ferramentas.py              agent tools: prever_risco, explicar,
                              avaliar_referenciacao, consultar_historico
  agente.py                   tool-using LLM agent (terminal)
  app.py                      Streamlit interface (patient assessment + agent chat)
  testar_agente.py            scripted conversations that test the agent
  run_all.py                  runs the whole pipeline in order
results/                      generated by the scripts
  tables/  figures/  models/
paper/                        IJCAI-27 paper: paper.tex, refs.bib, images/
```

Code comments and console output are in Portuguese, the figures and the paper are in English.

## Installation

Requires Python 3.11 or newer (tested with Python 3.14). From the project root (the folder containing `src/`, `data/` and `results/`):

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
```

Versions are pinned in `requirements.txt` (pandas, NumPy, SciPy, scikit-learn, XGBoost, joblib, Matplotlib, SHAP, Streamlit, anthropic).

## Reproducing the results

From the project root:

```bash
python src/run_all.py
```

This runs, in order: model comparison, calibration and threshold, final figures, fold-wise comparison, SHAP explanations, example cases, and the active learning experiments (fixed split and `--vary-split`). Tables, figures and the final model are written to `results/`. The script stops at the first error.

Use `python src/run_all.py --sem-active-learning` to skip the active learning step (about 2 minutes without it; each active learning run adds 1 to 2 minutes).

The scripts can also be run one by one, in this order: `comparar_modelos.py`, `limiar_calibracao.py`, `graficos_finais.py`, `comparacao_folds.py`, `explicar_shap.py`, `testar_casos.py`, `active_learning_ckd.py`, `active_learning_ckd.py --vary-split`.

The final model (`results/models/modelo_ckd_final.joblib`, model plus threshold) is produced by `limiar_calibracao.py`. If it does not load because of a different scikit-learn version, re-run scripts 1 and 2.

The `results/` folder in this repository already contains the outputs of a full run, so the results can be inspected without running anything.

## Physician interface

```bash
python -m streamlit run src/app.py
```

The app opens in the browser. In the sidebar, load a patient from the test set and click **Avaliar** to see the predicted probability, the decision at the chosen threshold, the SHAP explanation and the referral recommendation. A second tab lets you chat with the agent.

## Language-model agent (optional)

The agent calls four tools (`prever_risco`, `explicar`, `avaliar_referenciacao`, `consultar_historico`) on top of the trained model. It needs an API key set as an environment variable. Without a key, the patient assessment in the app still works. Never put the key in the code.

```bash
export OPENROUTER_API_KEY="sk-or-..."      # OpenRouter (Anthropic-compatible endpoint)
# or
export ANTHROPIC_API_KEY="sk-ant-..."      # Anthropic API
# Windows (PowerShell): $env:OPENROUTER_API_KEY="sk-or-..."

python src/agente.py                       # chat in the terminal
python src/testar_agente.py                # scripted test conversations -> results/agente_ronda1.md
python src/testar_casos.py --agente        # the 3 example cases through the agent
python -m streamlit run src/app.py         # or in the app, tab "Conversar com o agente"
```

The model can be changed with the `CLAUDE_MODEL` environment variable (default `claude-sonnet-5-5`). Agent answers can vary between runs, so the qualitative tests in the paper are not exactly repeatable.

## Design decisions

- **Split and test use.** Stratified 80/20 split with `random_state=42`. The test set is used once, for the final model.
- **Model selection.** Highest mean sensitivity in 5×10 repeated CV (training set only). If the difference to the best model is below one standard deviation, the models tie and the simplest one is chosen.
- **Threshold.** Chosen on out-of-fold predictions to reach a target sensitivity (`ALVO_SENS` in `src/limiar_calibracao.py`).
- **Uncertainty and deferral.** Probabilities between 0.25 and 0.75 are "uncertain" and the case is deferred to the physician (`ZONA_INCERTA` in `src/ferramentas.py`).
- **Explainability.** SHAP on the final model: `LinearExplainer` for logistic regression (log-odds), `TreeExplainer` for Random Forest and XGBoost. The script checks that base value plus the sum of SHAP values reproduces the model output, and counts how many of the top 5 variables are KDIGO markers (`sc`, `bu`, `al`, `sg`).
- **Referral criteria.** Simplified, KDIGO 2024-inspired. The dataset has no sex, so eGFR cannot be computed.
- **Agent safety.** If essential values are missing, the agent asks for them. Values outside the plausible ranges (`LIMITES` in `Prep_Data.py`) are refused and sent back to the physician for confirmation.
- **Example cases** (`testar_casos.py`), chosen on the test set: clear CKD is the highest-probability CKD patient, borderline is the patient closest to the threshold, healthy is the lowest-probability non-CKD patient.

## Paper

The paper uses the IJCAI-27 template and is in `paper/`. To compile it, put the official `ijcai27.sty` and `named.bst` in the same folder (they are not included in this repository), then run:

```bash
cd paper
pdflatex paper && bibtex paper && pdflatex paper && pdflatex paper
```

Paper figures are in `paper/images/`. The figures generated by the scripts are in `results/figures/`, and the numbers in the paper's tables come from `results/tables/`.
